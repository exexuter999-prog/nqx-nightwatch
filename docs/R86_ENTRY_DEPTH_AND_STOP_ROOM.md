# R86 押し目の深さと SL の余裕(ブラケットの平行移動)

2026-09-14。ユーザー相談「SL に 0.5pt 触れずに TP へ行ったトレードがあって怖い。建値を
もっと下げて SL にも余裕を持たせる設計にできないか」への回答。実装は `entry_depth.py`、
設定は `execution_contract.json` の `entryDepth`、検証は `tests/test_r86_entry_depth.py`。

## 0. 結論

1. **SL だけ広げる案は採らない。** VP80 の公開シナリオ全体では期待値が変わらず(±0.00R/件)、
   レベル型(BREAKER/TURTLE)では −0.03〜−0.04R/件。損切りの 7 割は SL を 1N 以上抜けて
   おり、広げても救えるのは少なく、広げた分だけ枚数が減る。
2. **建値と SL を同じ幅だけ深くする(平行移動)。** SL 幅 = リスク額・枚数は変わらない。
   ターゲット価格も変えない。変わるのは「約定したトレードの建値の良さと SL 余白」と
   「押しが浅くて約定しない取り逃し」だけ。
3. **場合分けは建値の錨で決まる。**

   | ケース | モデル | 建値 | 深くすると | 方針 |
   |---|---|---|---|---|
   | 錨なし | VP80_REVERSION | 直近の確定足終値 | 改善(+0.08〜+0.22R/件) | **0.25N 平行移動** |
   | レベル | BREAKER_CONTINUATION / TURTLE_SOUP_REVERSAL | レベルそのもの | 0.5N で悪化(逆選択) | 触らない |
   | OTE | OTE_FVG_PULLBACK | 0.62–0.79 の中点(既に深い) | 件数 3 で判定不能 | 触らない |

   N = ノイズ床(直前の確定 3 分足 12 本のレンジ中央値。SL 緩衝と同じ単位)。
4. **既定は SHADOW(記録のみ)。** LIVE にするのは `execution_contract.json` の
   `entryDepth.mode` を `"LIVE"` に変える 1 行。Worker のデプロイは不要(Python 側だけで完結)。

## 1. きっかけ: 実トレードの SL 余白

TP1(または SL)に届くまでに、価格が初期 SL へどこまで迫ったか(確定 3 分足の高安。
3 分足の極値は本物の極値なので、細かい足でも余白はこれより小さくならない)。

| JST | モデル | 方向 | SL | 最接近 | 余白 | 結果 |
|---|---|---|---|---|---|---|
| **09-08 19:54** | VP80 A+ | BUY | 29,533.50 | 安値 29,534.00 | **0.50pt** | TP1 → +$280 |
| 09-05 04:56 | VP80(記録上 UNATTRIBUTED) | SELL | 29,590.50 | 高値 29,587.00 | 3.50pt | +$1,288 |
| 09-08 18:57 | VP80 A | BUY | 29,568.50 | 安値 29,572.75 | 4.25pt | +$492 |
| 09-08 15:09 | BREAKER B | SELL | 29,644.75 | 高値 29,639.25 | 5.50pt | +$938 |
| 09-12 00:28 | VP80 A | SELL | 29,507.50 | 高値 29,499.50 | 8.00pt | +$1,415 |

逆向きの「わずかに刈られた」側: 09-09 07:06 VP80 BUY(SL を 0.75pt 抜け、108 分後に TP1)、
09-11 09:04 VP80 B BUY(1.0pt 抜け、144 分後に TP1)、09-10 01:10 VP80 BUY(1.0pt)。
ただしこの 2 件は刈られた後さらに 6.75pt / 15pt 深く押しているので、0.25N 程度の余裕では
どのみち救えない(§3.3)。

**ぎりぎりの勝ちは VP80 に集中している**(上位 5 件中 4 件)。

## 2. 測り方

- **足**: 監査バンドル `monitor_cycle_HHMM.json` の `snapshot.bars3m`、`tv_raw/bars3m.json`、
  台帳の `result.view.market.bars` と R57 決済チャートの和集合。**各配列の最終行(形成中の
  可能性)は捨てる**。出所間の食い違いは 0 件。
- **シナリオ**: 監査バンドルの `scenarios.primary`(ARMED + WATCH、221 セットアップ)。
  同じ (model, side, entry) の連続周期は最初の周期の幾何で 1 件。`cluster` 表示は
  同じ (model, side) が 20 分以内に撃ち直された塊を先頭 1 件にまとめた数え方。
- **約定規則(不利側に倒す)**: 価格が既に建値に届いていれば成行(engine の
  `_command_for_entry` と同じ判定)、そうでなければ指値で **1tick 突き抜け**を要求。
  約定前に TP1 に触れたら取消(R52)。約定足の TP1 は数えない。同じ足で SL と TP の両方に
  触れたら SL。TP1 後は runner の SL を建値へ。R は**計画の SL 幅**で割る(ULTRA が計画の幅で
  枚数を出すため)。
- **有意性**: セットアップ単位の対応ありブートストラップ(2,000 回)。90% 区間と P(改善)。

再現: `python entry_depth.py --report`(`--rest 60` で指値の待ち時間を変える)、
`python entry_depth.py --trades`。どちらも読むだけ。

## 3. 結果

### 3.1 勝ちは押してから伸びる / 負けは深く抜ける

| | 勝ち(TP1 到達)の押しの深さ | 損切りが SL を抜けた幅 |
|---|---|---|
| 全体 | 中央値 0.61N。**0.25N 以上押した 90%** / 0.5N 以上 63% / 1N 以上 27% | 中央値 1.69N。0.25N 未満 10% / 0.5N 未満 17% / 1N 未満 31% |
| VP80 | 中央値 0.61N。**0.25N 以上 94%** / 0.5N 以上 69% | 中央値 1.58N。0.25N 未満 11% |
| レベル型 | 中央値 0.64N。0.25N 以上 81% / 0.5N 以上 50% | 中央値 1.85N。0.25N 未満 7% |

- 勝ちの 14%(51 件中 7 件)が SL まで 0.25N 未満の余白で生き残っている = 「ぎりぎり」は
  偶然ではなく構造的に起きている。
- 損切りの 33% は 3 時間以内に TP1 へ届いている(方向は合っていた)。しかし SL を抜けた幅の
  中央値は 1.7N で、**少し広げても大半は救えない**。
- だから効くのは「SL を広げる」ではなく「**押してから入る**」。VP80 の勝ちの 94% は 0.25N
  以上押しているので、0.25N 深い指値でもほとんど取り逃さない。

### 3.2 場合分け(期待値の差 = 深くした場合 − 今のまま、R/セットアップ)

指値の待ち 30 分。括弧は 90% 区間、P は改善確率。

| ケース | 数え方 | n | 0.25N | 0.5N | 1.0N | SL だけ 0.5N |
|---|---|---|---|---|---|---|
| VP80 | 全件 | 131 | **+0.090** [−0.04, +0.22] P0.87 | +0.076 P0.77 | +0.015 P0.53 | +0.000 P0.48 |
| VP80 | 塊の先頭 | 33 | **+0.222** [−0.04, +0.53] P0.91 | +0.366 P0.95 | +0.503 P0.96 | +0.237 P0.95 |
| レベル型 | 全件 | 87 | +0.009 P0.59 | **−0.060** P0.26 | +0.042 P0.59 | **−0.036** P0.22 |
| レベル型 | 塊の先頭 | 76 | −0.011 P0.42 | **−0.051** P0.32 | −0.011 P0.47 | −0.029 P0.30 |
| OTE | 全件 | 3 | — | — | — | — |

待ち 60 分でも向きは同じ(VP80 全件 0.25N +0.075 P0.83、レベル型 0.5N −0.085 P0.18)。

読み方:
- **VP80 は深くすると改善する向きが一貫**しているが、区間は 0 をまたぐ(P0.83〜0.91)。
  「効くはず」の段階で、証明済みではない。深さは 0.25N が最も取り逃しが少なく、全件表示で
  最も良い。0.5N 以上は塊表示では伸びるが全件表示で落ちる(取り逃しの効き)。
- **レベル型は深くしない。** 建値がレベルそのものなので、レベルより深い約定は
  「レベルが崩れたときだけ約定する」逆選択になる(指値の約定確率と約定後の損益が逆相関する
  一般的な性質。Albers et al. 2025, arXiv:2502.18625 は BTC 無期限先物の実験で同じ構造を示す)。
- **SL だけ広げる**はレベル型で悪化、VP80 全件で効果ゼロ。平行移動より良い切り方は無い。

### 3.3 実トレードへの当てはめ(`python entry_depth.py --trades`)

VP80 と記録された実トレード 16 件(09-08〜09-12)に 0.25N 平行移動を当てると:

- **勝ち 7 件はすべて約定し、全件 TP1 到達。取り逃しは 0 件。** SL 余白は
  19:54 の 0.50pt → 3.75pt、18:57 の 4.25pt → 7.50pt、00:28 の 8.00pt → 15.25pt など、
  全件で 0.25N 分(3.25〜7.25pt)増える。建値も同じだけ良くなる。
- **負け 9 件のうち 8 件は負けのまま**(同じ −1R)。わずかに刈られた 07:06 / 09:04 も、その後
  さらに深く押しているので救えない。残る 09-10 01:10 は SL を 1.5pt 残して生き残るが、
  6 時間 TP1 にも届かず未決。0.25N は「ぎりぎりの勝ちを安全にする」深さであって、
  「負けを勝ちに変える」深さではない。

### 3.4 限界

- 期間は実質 2026-09-04〜09-11 の 1 週間強、ほぼ 1 つの相場環境。
- 監査バンドルは同じ HH:MM のファイルが翌日に上書きされるので、全周期の標本ではない。
- 3 分足の中の順序は分からない(不利側に倒してある)。
- 深い指値は約定しないまま残る時間が長くなり、その間は新規が塞がる(engine は
  `ENTRY_RESTING` を blocking とみなす)。この機会費用は §2 の単発シミュレーションには
  入っていない。1 ポジションずつ進める再生(約 27 約定)では合計が +18.0R → +14.9〜+16.7R と
  **むしろ下がった**。差の大半は「どの後続セットアップを取るか」の入れ替わりで、同じ
  トレード同士では平行移動の方が R も余白も良かったが、27 件の合計差(±5R 程度が誤差)を
  改善とは言えない。**合計損益の改善は未証明**で、確かなのは「同じトレードの SL 余白が
  0.25N 増える」ことと「取り逃しが少ない」ことまで。

## 4. 設計

### 4.1 入口と不変条件

`monitor_publish.enrich_decisive_strategy` が `msnr_gate.decision_to_scenario` で組んだ直後に
`entry_depth.annotate(out, scenario, noiseFloor)` を 1 回呼ぶ(`_apply_entry_depth`)。

- **判定は元の幾何のまま。** model / grade / state / decisionId / score はこの層で変えない
  (TP までの R が伸びて等級が上がる、を起こさない)。
- **SL 幅は不変。** `normalize_qty` / `execution_contract` / ULTRA / `order.py` / Worker の
  リスク判定はすべて同じ値を見る。ULTRA は TP1 までの距離が伸びる分、目標に必要な枚数が減る
  (リスク額は下がる側)。
- **ターゲット価格・脚は不変。** `targetR` だけ新しい建値で再計算。
- **二重に動かない。** pipeline と publish で 2 回評価されるが、毎回 decision から作り直した
  元の幾何に掛けるので同じ結果。
- **失敗は OFF に倒す。** 契約が読めない・形が壊れている・ノイズ床が無い・tick 外・
  ターゲットの内側に建値が来る、のいずれでも動かさない。この層の例外で監視サイクルは落ちない。
- 0.25N は tick へ半切り上げ、`maxDepthPt`(10pt)で頭打ち。

### 4.2 モード

| mode | 公開シナリオ | バンドル `entryDepth` | 注記 | 証跡タグ |
|---|---|---|---|---|
| OFF | 元のまま | 書かない | なし | なし |
| **SHADOW**(既定) | 元のまま | 「動かした場合」を記録 | `R86 entry depth … [SHADOW: not applied]` | なし |
| LIVE | entry / stop を置換 | 記録 | `R86 entry depth … [LIVE]` | `ENTRY_DEPTH_025N` |

LIVE のタグは `evaluation.decision.evidence` → 凍結プラン `decisionEvidence` →
スコアカード `evidenceTags` に流れる。R48 と同じく**記録専用**で、採点にも武装にも使わない。
平行移動したトレードだけの PF をスコアカードで切り出すための鍵。

### 4.3 契約

```json
"entryDepth": {
  "version": "R86-ENTRY-DEPTH-1",
  "mode": "SHADOW",
  "stopShift": "SAME_AS_DEPTH",
  "maxDepthPt": 10.0,
  "rules": [{"case": "VP80_CLOSE_ANCHOR", "models": ["VP80_REVERSION"], "depthN": 0.25}]
}
```

`stopShift` は `SAME_AS_DEPTH` 以外を受け付けない(SL だけ広げる設定は書けない)。
`depthN` は 0 < x ≤ 1.0。

## 5. 切り替えと撤退(事前登録)

- **SHADOW → LIVE**: ユーザー判断。根拠は §3.2 / §3.3。数字を足したいなら SHADOW のまま
  数日回して `python entry_depth.py --report` を見直す。
- **LIVE → OFF(撤退基準)**: 平行移動した VP80 の実トレードが 30 件たまった時点で、
  (a) スコアカードの `ENTRY_DEPTH_025N` 付きの PF がタグ無しの VP80 を下回る、または
  (b) `--report` の VP80 全件で 0.25N の差が負かつ P(改善) < 0.2、または
  (c) 平行移動した指値の TP1 先行取消が 40% を超える、のどれかで `mode` を戻す。
- **深さ・対象の変更は新しい version**(`R86-ENTRY-DEPTH-2`)。同じ名前で数字だけ動かさない。
  レベル型への拡張は、そのケースだけで 100 件以上たまってから。

## 6. 見つけたが今回は触っていないもの

- **TURTLE_SOUP の SL が 2 本型スイープの破壊足の極値を含まない。**
  `msnr_gate._chain_prices`(`msnr_gate.py:1881-1893`)は `sweepBarT`(= 奪還足)1 本の
  安値/高値だけで SL を置く。2 本型(破壊足 → 2 本以内に奪還、`msnr_gate.py:400-404`)では
  より深い破壊足のヒゲの**内側**に SL が来うる。これは「SL の余裕」の構造的な穴だが、
  等級・目標・同一性キーまで変わるので別途リプレイしてから直す。
- **SL の丸めが最近接。** `_tick_price` は最近接の tick に丸めるので、SL が最大 0.125pt
  内側へ寄ることがある。同一性キー(SL を含む)が動くため今回は据え置き。
- 日足・セッション別の深さ(例: 高ボラ帯は 0.25N 止まり、低ボラ帯は 0.5N 以上が伸びる傾向)は
  セルあたりの件数が 20〜50 しかなく、今回はルールにしていない。
