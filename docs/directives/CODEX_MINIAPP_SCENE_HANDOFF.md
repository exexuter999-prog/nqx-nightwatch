対象: [telegram_mini_app/scene3d.js](telegram_mini_app/scene3d.js)(全面書き直し済み)

前状態は「線・多面体・光点の寄せ集めで何を描写しているか分からない」ため破棄した。
本書は**何を作ったか**ではなく、**触ると壊れるもの**と**なぜこの形なのか**を残す。

---

## ⚠️ 最優先: 壊してはいけないもの

### 1. `app.js` は1行も変更していない

Telegram ブリッジ・`sendData`・SEND DEMO・安全表示・シナリオ定義は無傷。
背景シーンの都合で app.js に手を入れないこと。

隠し要素のトリガー(後述)も**すべて scene3d.js 内に閉じてある**。
DOM リスナーが必要だったが、あえて scene3d.js から `.brandlock h1` を
拾いに行く形にした。app.js の差分をゼロに保つため。

外部インターフェースは従来どおり1つだけ:

```js
const scene3d = initNightwatchScene(canvas);
scene3d.setMode("long" | "short" | "neutral");
```

### 2. コンソールを絶対に覆わない

**このルールだけは推測で実装していない。** DOM を実測し、投影して
画面座標で測り直し、収束するまで補正するループになっている。

```
computeLayout()
  → .app-shell の offsetTop+offsetHeight で下端を測る
  → リグを配置
  → projectedBounds() で実際の投影を画面px で測る
  → ずれを補正して再配置(最大6パス)
  → 最後にハードクランプ: それでも上に食い込むなら縮める
```

`CLEARANCE = 24`(px)がコンソール下端との最小間隔。

**なぜ実測なのか:** リグは奥行きを持つので `z=0` 前提のpx換算では
投影サイズを過小評価する。初回実装で15px食い込んだ。
またウェブフォントが載るとコンソールの高さが変わるので、
`ResizeObserver` と `document.fonts.ready` の両方で再レイアウトする。

再レイアウトのトリガー(`layoutDirty = true`)を消さないこと:

| きっかけ | 理由 |
|---|---|
| `resize` | 当然 |
| `ResizeObserver(.app-shell)` | **SEND DEMO でパネル高さが変わる**(モード変更を伴わない) |
| `document.fonts.ready` | blackletter が載るとロゴの高さが変わる |
| `setMode()` | プレビューパネルの開閉 |
| `setSigil()` | 構図が切り替わる |

### 3. 抽象装飾を足さない(ユーザーの明示指示)

線・多面体・粒子・意味のないグリッドは禁止。
「一目でモチーフを説明できる造形」であること。

実際に一度**霧の光条コーン**を入れたが、ハードエッジの半透明ウェッジに
なって「貼り付けた図形」に見えたので**削除した**。同じ轍を踏まないこと。
装飾を足したくなったら、**その部品が物理的に何であるかを説明できるか**で
判断する。

## 何を描写しているか

**検量天秤(ナイフエッジ梁天秤)を、1灯の投光器が照らしている。**

| 部位 | 実装 |
|---|---|
| 定盤 | 黒御影石スラブ + 3点調整脚 |
| 支柱 | 鋳鉄、上端にメノウのナイフエッジ受け |
| 梁 | 真鍮の三角トラス(下弦・頂点ポスト・斜材・中間束) |
| 皿 | 真鍮のLathe皿 + 3本ロッドのスターラップ吊り |
| 指針 | 支点から下向き、目盛板(InstancedMesh 23本)を指す |
| 制動器 | 梁を持ち上げて水平固定するフォークとレバー |

### 第3の目 = 照明器具そのもの(ユーザー要望)

紋章を描いたのではなく、**この場を照らしている実在の器具**として設計した。

カウンターウェイト付きブームに吊られた投光器。フード、研磨リフレクター、
すりガラスレンズ、**8枚羽根の機械式虹彩絞り**、そして
**3本のアームを3本の弦で筋交いした光学スパイダー**。

正面から見るとスパイダーが瞳を囲む三角形になる。
これは装飾ではなく、重いレンズ頭部を保持するための実際の構造
(反射望遠鏡のスパイダーと同じ)。

**色分けは光源が持つ。** 部品に色を塗っていない。
ランプが LONG=acid / SHORT=rust / neutral=violet に変わり、
シーン全体がその色になる。目盛板は無着色の計器のまま。

## ヒーローアニメーションは1種類

**固有のタイムラインを持つのは梁だけ。** 他はすべて従属動作。

```js
class Body   // 減衰2次系 + 機械的ストッパー(反発係数付き)
ζ = 0.25, ω = 7.0 rad/s
```

gsap のトゥイーンではなく**毎フレーム積分**している。
これが重量感の出どころなので、イージング付きトゥイーンに
置き換えないこと。

実測した挙動:

```
0.12s  制動器が外れるまで梁は動けない(溜め)
0.61s  -7.21° までオーバーシュート
2.3s   -5.02° に収束
```

従属動作:
- スターラップ(梁の角加速度で駆動、梁より長く揺れ続ける)
- 指針とその**残像リボン**(速度が閾値を超えたときだけ表示)
- 皿の**アフターイメージ**(3枚、速度連動)
- 目の視線(τ≈0.31s の遅れ追従)
- 虹彩絞りの開閉

**停止姿勢の設計:** neutral へ戻すとき、梁が収まるのを待ってから
制動器を上げて噛ませる(`engageArrest()`)。
これが「ガチャン」と終わる感触を作っている。3.6s のフォールバックあり。

## LONG / SHORT と光の当たる皿

**照明は梁の上にあるので、上がった皿が光に近づき、沈んだ皿は影に落ちる。**

| | 沈む皿 | 光が当たる皿 |
|---|---|---|
| LONG | 右 | **左**(acid green) |
| SHORT | 左 | **右**(rust) |

### ハマった罠: 照明器具は支点の真上でないと機能しない

最初 rig x=+1.0 の片寄った位置に吊っていた。すると
**視線をどちらに向けても近い側の皿が明るくなり、視線が意味を失う。**
逆二乗則が視線の効果(±1.33)を上回るため。

`boomTo` の x を 0.05(ほぼ支点直上)にして解決。
**ここを動かすなら左右対称性を壊していないか確認すること。**

## 隠し要素(イルミナティ / 第3の目)

トリガー: `1776` とタイプする、または **NIGHTWATCH ロゴを1.6秒長押し**。

```
灯りと環境反射が落ちる → 機械が闇に沈む
梁は制動器で水平に固定される
投光器が皿の監視をやめてカメラを向く
絞りが全開になる
→ ベゼルリング・スパイダーの三角形・燃える瞳だけが残る
```

キャプション: `ANNVIT CŒPTIS · NOVVS ORDO SECLORVM · MDCCLXXVI`

7秒で自動復帰。タップ・キー入力で即解除。`setMode()` でも解除される。
**表示中もコンソールは覆わない**(実測 81px の余白)。

構図は `computeLayout()` の3つ目の分岐で、
**リグ全体ではなく投光器ヘッドだけをバンドにフィット**させている。
残りの機械はその時点で無灯なので黒に沈んで見えない。

## three.js 固有の落とし穴(全部踏んだ)

### 1. `Object3D.lookAt()` はカメラ・ライト以外だと +Z を向ける

three.js は Camera / Light 以外で**引数を入れ替える**ため、
プレーンな `Group` では **+Z** がターゲットを向く(-Z ではない)。

投光器は -Z 向きに組んであるので、`gimbal`(照準用)の下に
`head.rotation.y = Math.PI` でぶら下げている。

**症状:** これに気づくまで、器具が真後ろを向いて何も照らしていなかった。

### 2. メタルは環境マップが無いと真っ黒になる

`metalness` が高いマテリアルは拡散反射がゼロなので、IBL が無いと
小さな鏡面ハイライト以外は黒く潰れる。

`buildEnvironment()` で PMREM の室内環境をインライン生成している
(暗い箱 + 暖色パネル1枚 + 寒色パネル1枚)。
`three/examples` に依存させたくなかったので手書きにした
— index.html の importmap フォールバックを壊さないため。

`scene.environmentIntensity = 2.05` が真鍮の見え方を支配している。

`pmrem.fromScene(room, sigma)` の sigma は 0.05 だと
`too large and will clip` の警告が出る。**0.02 にしてある。**

### 3. 虹彩絞りの開口は羽根の「先端」では決まらない

羽根は幅を持つので、実際の開口半径は
**`Rp·sin(α) − 羽根の半幅`**(軸から羽根の長辺までの垂線距離)。
先端位置で計算すると、開いているつもりで完全に閉じる。

`IRIS_SWING = 1.35` がその補正込みの値。

### 4. レンズを絞りと一緒に縮めない

最初レンズ自体をスケールしていたので、羽根の裏に隠れて瞳が
まったく光らなかった。**レンズは常に全径**、遮蔽は羽根の仕事。

### 5. `prefers-reduced-motion` で光量が固定される

ランプの光量更新を `if (!still)` の中に置くと、reduced-motion 時に
モードを変えてもランプが初期値のままになる。分岐の外に出してある
(ちらつきだけを `flicker = 1` で殺す)。

## バウンディングボックスの扱い

`solidBounds()` は**実体だけ**を測る。
光は物質ではないので、以下は `userData.noBounds = true` で除外:

- 床平面
- 指針の残像リボン
- 皿のアフターイメージ

**除外を忘れるとレイアウトが破綻する。**
実際、削除前の光条コーンを含めていたせいで、
スケールも配置も狂ってコンソールに食い込んだ。

## 補足: なぜこの設計なのか

ユーザーからの指示は明確だった。

> 抽象的な線、多面体、粒子、意味のないグリッドは禁止。
> 一目でモチーフを説明できる造形にする。
> 「地下聖堂」「蛇」「監視室」などの単語を、そのまま線や記号で表現しない。
> 実在する空間・物体として構造、素材、照明、動作原理を設計すること。

だから「天秤の絵」ではなく**天秤という機械**を組んだ。
第3の目も「三角形と目のマーク」ではなく
**三脚スパイダーと虹彩絞りを持つ実在の投光器**にした。

改修する際も、追加する部品について
**「これは何で出来ていて、どう動くのか」**が答えられることを基準にしてほしい。
答えられないものは、この背景では装飾にしかならない。
