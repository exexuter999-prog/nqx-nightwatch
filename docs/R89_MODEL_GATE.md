## 0. 結論

- **「TURTLE 全体に優位性が無い」とまでは言えない。** 負けが集中しているのは **先回り指値型**
  (MSS 確認後、リテスト前にレベルへ置く指値。R26 の `LIMIT_ENTRY_STATES`)。リテスト保持型は件数 4 で判定不能。
- 外しても再生の合計は悪化しない(+0.2〜+1.0R)。改善幅は誤差の範囲。
- スイッチは入れた(既定は空 = 何も外さない)。**2026-09-14 07:34 JST、ユーザー決定で
  `TURTLE_SOUP_REVERSAL` を `ALL` で外した**(指値型だけ外す案と再生の合計は同じ。リテスト保持型の
  候補は WATCH の記録としてだけ残る)。導入直後のサイクル(07:36)は READY / publish とも正常。

## 2. スイッチ

```json
"modelGate": {"version": "R89-MODEL-GATE-1", "disabled": []}
```

- `disabled` の各行 `{"model": "...", "variant": "ALL" | "RESTING_LIMIT"}`(variant 省略は ALL)。
  - `ALL` … そのモデルの候補すべて。
  - `RESTING_LIMIT` … `restingLimit` の候補だけ(現状 TURTLE_SOUP_REVERSAL の先回り指値だけが持つ)。
- 当たった候補は `hardBlockers` に `MODEL_DISABLED` / `RESTING_LIMIT_DISABLED`、`state=WATCH` で**記録には残る**が、
  primary には選ばれない(別モデルが primary になれる)。重複除去の前に分けるので、外した指値型が同じ side の
  リテスト保持型を押し出さない。
- 空配列・節なし・壊れた節は何も外さない(R89 以前と同じ判定。再生 1,219 件でバイト一致を確認)。
  不正な行はその行だけ無視されるので、書き換えたら次で確かめる(読むだけ):
  `python -c "import msnr_gate; print(msnr_gate.model_gate_rules())"` → `invalid` が空であること。
- Python(msnr_gate)だけで完結。Worker のデプロイは不要。次の監視サイクルから効く。

外した場合の撤退基準: 外した型の候補を記録から再生し、30 件たまった時点で平均 R が正(90% 区間の下限 > 0)なら戻す。
