# R88 TURTLE の SL をスイープ全体の極値へ(スイッチ・既定 OFF)

2026-09-14。R86 §6 で見つけた穴の定量と修正案。実装は `msnr_gate.py`
(`sweep_stop_mode` / `_sweep_origin_index` / `scan_chain` / `_chain_prices`)、検証は
`tests/test_r88_turtle_sweep_stop.py`。**本番は OFF のまま。有効化はユーザー判断。**

## 0. 穴

`_chain_prices` は TURTLE の SL を `sweepBarT`(= 奪還足)1 本の極値で置く。`_is_reclaim_bar` は
2 本型(破壊足が 1〜2 本前にゾーン外で引け → 奪還)も受けるので、破壊足のヒゲが奪還足より
深いと、SL が**実際に刈られた価格の内側**に来る。

## 1. 再生(読むだけ)

監査バンドル 1,219 件(08-13〜09-12、同じ HH:MM は上書きされるので全周期ではない)を
現行コードで再評価(記録済み判定との一致 1,172/1,185)し、SL だけを「破壊足〜奪還足の極値」
に替えた版と比較。成績は R86 と同じ保守的規則(確定 3 分足・指値は 1tick 突き抜け・
約定前 TP1 で取消・同じ足は SL 優先・指値待ち 30 分・6 時間)。

| 項目 | 数 |
|---|---|
| 候補になりうる SWEEP 連鎖(RETEST_HELD / MSS_CONFIRMED、重複除去) | 79。**2 本型 50(63%)** |
| うち破壊足の極値が奪還足より深い | 36/50。深さ中央値 6.0pt・p75 21.75pt・最大 131.25pt(中央値 0.39N) |
| TURTLE 候補(side ごとの重複除去後、固有セットアップ) | 40(2 本型 31)。**SL が動く 22(55%)**、動く幅の中央値 ≈4pt・最大 95.5pt |
| SL が既にスイープのヒゲの内側(建てる前に SL 価格を通過済み) | **2/40**: 09-11 02:25 JST BUY C:VAL(**実トレード ea03f616…、26→56.25pt**)/ 09-11 21:52 BUY(WATCH) |
| リスク > 50pt($200・2 枚) | 8 → 13 |
| リスク > 60pt(msnr 上限 → RISK_CAP_EXCEEDED) | 6 → 10 |
| ARMED の固有 TURTLE | 11 → 12(09-11 23:19 SELL が 66pt で ARMED→WATCH、09-10 09:54 SELL が WATCH→ARMED 等) |
| 周期の decisionId が変わる | 50/1,219(うち primary のモデルが入れ替わる 16) |

成績(SL が動いた 22 件のうち、どちらかで ARMED かつ約定したもの 5〜6 対):

| 待ち | ΣR 現行 → 修正 | Σpt(1 枚平均)現行 → 修正 |
|---|---|---|
| 30 分 | −3.14 → −2.40 | −99.9 → −102.8 |
| 60 分 | −4.14 → −3.40 | −125.9 → −159.0 |

- 09-10 01:13 SELL は −1R → +0.6R(修正 SL を 1.25pt 残して生存)。09-11 23:19 SELL は +0.86R の勝ちが
  60pt 上限で見送りに変わる。残りは両方 −1R。
- 参考: 現行の ARMED 固有 TURTLE 11 件は約定 7(TP1 到達 2)、約定分の平均 −0.155R。TURTLE 自体の
  エッジも未証明。
- 実トレードの TURTLE は 2 件(両方 ULTRA 指値・損切り)。09-11 分は上表のとおり修正 SL でも
  損切り(待ち 60 分で SL 抜け 0.5pt)。09-05 01:07 JST 分はバンドルが上書き済みで再構成していない。

## 2. 判断材料

- 穴は珍しくない(候補の過半で SL が動く)。「SL は構造否定価格の外」という原則には修正版が合う。
- 成績差は件数 5〜6 で R では +、pt では − に割れ、誤差と区別できない。**改善は言えない。**
- 変わるもの: SL・targets/targetR・score/grade・RISK_CAP_EXCEEDED・`setup_identity`(SL を含む)=
  decisionId。切り替え直後は同じ構造が別 ID になり、重複防止が別セットアップとして数え直す
  (**建玉・未約定指値が無いときに切り替える**)。

## 3. スイッチ

環境変数 `NQX_TURTLE_SWEEP_STOP`。`LIVE / ON / 1 / TRUE / YES` だけが有効、それ以外(未設定含む)は OFF。
監視ループを起動するシェルで設定する(pipeline と publish の両方が同じ値を読む)。

- **OFF(既定)**: R88 以前と完全に同じ。再生 1,219 件で判定・候補・レベルがバイト一致。chain にキーも足さない。
- **LIVE**: 2 本型は `min(破壊足〜奪還足の安値) − 緩衝`(SELL は鏡像)。chain に
  `sweepOriginBarT / sweepExtreme / sweepExtremeBeyondReclaim`、SL が実際に動いた候補に記録専用タグ
  `SWEEP_STOP_FULL_SPAN`(確認要素・採点には入れない。スコアカードで切り出す鍵)。
  1 本型・BREAKER(FLIP)・OTE・VP80 の SL は変わらない。

撤退基準(LIVE にした場合): タグ付き TURTLE が 30 件たまった時点でタグ無し TURTLE の PF を下回るなら OFF。
