# R65 — 目の駐在所(ペット)と独り言

2026-09-07 ユーザー要望: 「ノーシナリオの時に出る丸い目を、出現していないときはワイドで開いた
ウィンドウの左下の空間にペットとして駐在させて。状況に応じたシックな一言を吹き出しでつぶやかせて。
トレードの結果で一喜一憂する反応が見たい」。

## 何をしたか

### 1. 目が住む場所を 2 つにした(`app.js` / `eye3d.js` / `styles.css`)

R60 の 3D 眼球は待機カード(NO SCENARIO)の中にしか出ず、シナリオ・建玉・注文・GATES のカードに
変わると消えていた。実運用では評価が届いている限り GATES カードが出るので、**目はほとんど出ない**。

居場所を `mountStandbyEye()` が毎回決める。

| 条件 | 目の居場所 |
| --- | --- |
| WATCH タブに待機カードが有る | 従来どおりカードの中(`.standby`) |
| それ以外(シナリオ・建玉・GATES・他タブ) かつ 880px 以上・高さ 760px 以上 | 左下の駐在所(`.pet-eye`) |
| 狭い画面 / WebGL 無し | どこにも出ない(従来と同じ) |

- canvas は**1 枚のまま**移る(WebGL コンテキストは 1 つ)。`attach()` は置いていく側の `has-3d` を
  外す(残ると駐在所に空の丸が残る)。`detach()` は既に外れていれば即 return(毎秒呼ばれるため)。
- 駐在所は `position: fixed` の左下。880px では横並びドックの上、1100px 以上ではドックが左端の
  縦レールになるので床まで下ろす。**左端には貼り付けない**(2026-09-07 追補「もう少し真ん中に
  寄せて」): 本文の左端から更に 48px 内側。幅は 300px に抑える —— 側柱の帯(最大 330px)を
  越えないので、どの段でも本文の列(`.ops`)に被らない。
- 面は `pointer-events: none`。触れるのは台座(`.pet-perch`)だけで、突くと独り言を引き直す。
- 寸法は **1.7 倍**(2026-09-07 追補): 目 116 → 197px、吹き出しは `--t-note` 11px → 15px、
  角丸・余白・尻尾も一段大きい面(`--r-card`)へ。吹き出しは `width: max-content` で文字なりに縮む。
- 縦に余裕の無い窓では出さない(側柱が下まで伸びると重なるため `min-height: 760px` で切る)。
  この閾値は CSS と `app.js` の `matchMedia` の **両方**に有る。片方だけ変えると、display: none の
  host に目を入れて canvas が 0 幅で焼かれる。

### 2. 状況に応じた独り言(`pet.js`)

`nqx_state.py` の verdict と同じ声 —— 短く、乾いていて、少し尊大な英語の一行。台詞は seed から
決定論で引く(同じ場面では同じ台詞。3 秒ごとの再描画でパタパタしない)。90 秒ごとに拍が進んで
入れ替わる。

- **場面(独り言)**: `kill / offline / halt` → 建玉(`posUp / posDown / posRun`)→ `order` →
  `armed` → `watching` → `offduty / silent` → 今日の実現損益(`dayUp / dayDown`、拍が偶数のときだけ)
  → `blocked` → `idle`。
- **出来事(反応)**: 決済 > TP1 > 約定 > 建玉消滅 > 送信 > 武装 の順に 1 つだけ。sound.js と同じ
  規律で **前後の view の差**からしか拾わず、起動直後の 1 件目は基準として飲み込む(開いた瞬間に
  前夜の決済を喜ばない)。決済は 40 秒、他は 16 秒だけ独り言を上書きする。
- 決済の重さは `ledger.js` の `deriveTrade` から: `winBig`(≥1.8R または ≥$400)/ `win` /
  `flat`(コスト帯)/ `loss` / `lossBig`(≤−1.5R または ≤−$500)。式は二重に持たない。
- 吹き出しの色は tone(`up` = 朱の縁と灯り / `down` = 錆 / `warn` = 薄い朱 / `dim` = 無色)。

### 3. 一喜一憂(`eye3d.js` の場面表)

`MODES` に `elated` と `dejected` を足し、瞼の重さの倍率 `lid` を全ての場面に持たせた。

- `elated`: 瞼が上がり(lid 0.3)、瞳が開き(0.47)、残り火が強い(0.34)、視線が忙しい(2.2)。
- `dejected`: 瞼が落ち(1.9)、瞳が締まり(0.30)、光が消える(0.01)、ほとんど動かない(0.45)。
- 決済の反応の拍だけ、台座が跳ねる(`pet-startle`)/ 沈む(`pet-sag`)。

**同時に直した実装の穴**: 描画ループは場面の**行そのもの**を `pupilAngle()` へ渡すのに、中では
`mode?.name` を見ていた(行に `name` は無い)。そのため R60 以来、武装しても瞳が neutral のまま
だった。行を直接受けられるようにした。

### 4. 目の周りの構造物(2026-09-07 追補「もっと凝って設計して」)

要点は **動く物と動かない物を分けること**。据え付けの筐体があると、目は宙に浮かず「取り付け
られた計器」に見える。

- **据え付け(回らない)**: バレル(眼窩の奥行きを作る筒・内壁だけ見せる)、4 分割のカラー
  (切れ目は受け金具の位置)、ベゼルからカラーへ橋を架ける受け金具 4 本とリベット、
  12 時の朱の基準マーク(場面の残り火 `glow` に連動して明るさだけ変わる)。
- **回る**: 環と目盛(時計回り 80 秒)、七芒星(**逆回り** 62 秒)、その間の帯を走る副尺
  (逆回り 47 秒、`InstancedMesh` 1 本 = 描画 1 回)。
  「星と線を逆方向に回して」(同日ユーザー指示)は、環と星を別の群に分けて回転符号を反転。
- 半径の帯は詰まっている: ベゼル 1.15〜1.25 / 目盛 1.19〜1.36 / 環 1.38 / 副尺 1.394〜1.430 /
  カラー 1.440〜1.484。視野は半径 1.533(camera 28°, z=6.15)まで。**空いている帯にしか置けない**
  —— 一度 1.245 に副尺を置いて、ベゼルと七芒星に重なって潰れたので外へ出した。

### 5. 声(2026-09-07 追補 — 三転して、実在の男性音声に落ち着いた)

| 版 | 作り方 | 結果 |
| --- | --- | --- |
| 1 | 女性音声(SAPI Zira)を 112Hz 固定ピッチのチャネルボコーダへ | 「ロボットすぎる上に何を言っているか全然聞き取れない」→ 破棄 |
| 2 | 素の女性音声を明瞭化(−1.4 半音・子音帯+)| 「呪われた野原しんのすけ」→ 破棄 |
| 3 | **Edge のニューラル TTS(`edge-tts`)の男性音声** | 採用 |

**なぜ 1・2 が失敗したか**: ピッチを下げても**声道の長さ(フォルマント)は変わらない**。
女性音声から低い男性音声は作れない —— 下げるほど「小さい人が低い声を出している」不自然さと
不明瞭さだけが増える。この PC の SAPI / OneCore には英語の男性音声が 1 つも無い
(Zira = 女性、Ayumi / Haruka / Ichiro / Sayaka = 日本語)ことを実測で確認したうえで、
ユーザー合意のもと `edge-tts` を導入した。

- 生成: `python tools/voice/neural.py --voice en-US-ChristopherNeural --rate=+2% --pitch=-14Hz --out public/voice`
  (引数は `--opt=value` の 1 要素で渡すこと。`-4%` は argparse がオプションと誤読する)
- **開発時に一度だけ**の生成で、アプリの実行時にネットワークへ出ることはない(WAV を同梱)。
  外へ出るのは `lines.json` の 8 語句だけ。
- 候補の実測(`neural.py --list`、`--pitch=-10Hz` 適用時):

  | 声 | F0 | 500Hz 以下の割合(太さ) |
  | --- | --- | --- |
  | Andrew | 119Hz | **0.43** |
  | Brian | 117Hz | 0.27 |
  | Steffan | 108Hz | 0.25 |
  | Roger | 102Hz | 0.21 |
  | Christopher | 118Hz | 0.21 |
  | Eric | 113Hz | 0.19 |
  | Guy | 168Hz | 0.19 |

  基本周波数が最も低いのは Roger だが、**胸に響く帯域の割合**(= 聴感上の太さ)は Andrew が
  突出している。声色の好みは耳で決めるものなので、7 声の試聴 WAV を渡して選べるようにした。
- **キレ(2026-09-07 追補「もっと自信に満ち溢れたキレのある声に」)**: 声色ではなく
  **立ち上がりと間**で決まる。(a) 話速を速める(`--rate=+12%`)、(b) 子音帯 2.2〜5.6kHz と
  3kHz 以上の棚を上げる、(c) レベラーが均した語頭の一撃を `snap()` で戻す、(d) 合図と声の間を
  120ms → 50ms、語尾の余韻を切る。結果、全キューが 0.77〜2.22 秒(前は 0.84〜2.45 秒)で、
  子音の割合は "Executed." 0.62 / "Gain secured." 0.68 / "Armed. Stand by." 0.77。
- 声は **en-US-ChristopherNeural**(Reliable / Authority)を採用。同じ文での実測で 2kHz 超の
  割合が最も高い組(0.57)かつ crest 6.46 —— 太さの Andrew(0.31)より「キレ」側に振れる。
  低さだけなら Roger(F0 102Hz)だが細く、権威の音にはならない。
- **厚み(2026-09-07 追補「もう少し厚みを持たせて」)**: 胸の帯(110〜340Hz)を足す。ただし
  **飽和とレベラーの後に足すこと** —— 前に置くと均される側に回り、ゲインを 0.42 → 1.10 と
  2.6 倍にしても厚みは 0.200 → 0.209 しか動かなかった(実測)。後段へ移して 0.95 にすると、
  8 キュー平均で厚み(100〜500Hz)0.314 → 0.381(+21%)、キレ(2kHz 超)0.459 → 0.398(−13%)。
  **まだ薄いという評価を受けて 3 層構造にした**: 胸の帯(140〜420Hz を ×1.6)+ **その帯の倍音**
  (`tanh` で作る。電話やノート PC は 200Hz 以下をほとんど鳴らさないので、帯を上げるだけでは
  そういう端末で厚みが消える)+ 基音(70〜130Hz)。HP も 58Hz まで下げた。結果 厚み **0.422**
  (キレ版比 +34%)、キレ 0.360。話速も +12% → **+2%**(ユーザー「もう少しゆっくり」)、
  ピッチ −14Hz。
- **音量(2026-09-07 追補「もう少しボリュームを大きくして」)**: 山ではなく **RMS で揃える**。
  山だけ 0.86 に揃えると、間のある台詞(「Armed. Stand by.」)が他より 3dB 小さく聞こえていた。
  RMS を目標へ寄せてから速い追従の limiter で天井 0.97 を守り、レベラーの狙いも 0.22 → 0.34、
  語頭を残す量(`ATTACK_KEEP`)は 0.35 → 0.18(山を立てるほど平均音量は下がる)。合図も 0.30 → 0.38。
  結果 **平均 −15.2 → −12.2 dBFS(+3.0 dB)**、クリップ 0 サンプル、厚み 0.418 / キレ 0.364 は維持。
  アプリ側の再生は元から `volume = 1` なので、音量は音源側でしか稼げない。
- 仕上げの前段は最小限(16kHz へ落とす → HP 70Hz → 子音帯 → 緩いレベラー → 立ち上がり →
  柔らかい飽和 → 胸の帯 → 正規化 → 合図)。素材が良いので金属質な加工はしない。
- オフラインの予備手段として SAPI 経路(`synth.ps1` + `voicefx.py`)を残す。
  `synth.ps1` は **UTF-8 BOM 必須**(PS 5.1 は BOM 無しを ANSI と読み、param ごと構文エラー)。

**台本(ユーザー指定)**と、それに伴うキューの分割:

| キュー | 文言 |
| --- | --- |
| 武装シナリオ | Armed. Stand by. |
| 手動で注文 | Manual fire. |
| 自動発注 | Auto deployed. |
| 約定 | Executed. |
| TP1 約定 | One down. |
| 決済(勝ち) | Gain secured. |
| 決済(負け) | Cut loose. |
| SOUND ON | Comms active. |

台本の正本は `tools/voice/lines.json`(`neural.py` と `synth.ps1` の両方が読む)。
`POSITION_CLOSED` を **勝ち / 負けの 2 つに割った**。どちらを読むかは、同じ更新に決済の記録が
届いていれば `ledger.js` の `deriveTrade`(価格から)、無ければ直前に見えていた建玉の含み損益、
どちらも取れなければ **勝ちとは読まない**(無い喜びを鳴らすより静かな方を読む)。
`CUE_TEXT` と `lines.json` の一致、WAV の実在、キュー数はテストで縛る。

### 5.5 眼球の作り込み(2026-09-07 の追補 6 本)

| 指示 | したこと |
| --- | --- |
| 白目の赤黒い血管を増やして | 網を 3 → 5 層(幹 2・枝 2・毛細)。幹を 2 本の別網にしたのは、1 本だと流れが揃って櫛に見えるため。血の色も `(0.20,0.025,0.03)` → `(0.155,0.016,0.022)` |
| 黒目の中の赤い淵を無くして | 虹彩側の発光を `emis = 0.0` に固定。さらに**朱のリムライトを強膜だけに掛ける**(`rimMask`)—— 黒目を暗くした分、同じリムでも虹彩が面ごと赤く染まっていた |
| リアルな瞳孔のふち | 一度 crenation(波打つ縁)を入れたが「ギザギザではなく滑らか」と却下 → 縁は真円・滑らか(±0.02rad)に戻し、立体は**陰影と視差**へ移した |
| 表面的じゃなく立体的に | (a) 虹彩は瞳へ落ち込む漏斗 —— 法線を径方向へ傾ける(`irisSlope`)、(b) 縁の外に接触の影、(c) **視差**: 面に沿った視線成分で瞳の判定をずらし、穴が奥に開いて見える(`uViewLocal` を毎フレーム更新) |
| 瞳孔以外の黒目をもっと黒く | `hot/mid/deep` を 0.034/0.018/0.003 → 0.024/0.013/0.0018。※ 一度 0.016 まで落としたら瞳(2)と虹彩(6-10)の差が 5/255 になり **縁が消えた**。「黒く」の下限は縁が読めるところ |
| 白目と黒目の境目が幅 1px 真っ白 | 原因は強膜側の充血が `smoothstep(uIris, …)` で縁ちょうど 0 から始まり、地の骨色が線で出ていたこと。開始を 0.012rad 内側へ移し、**輪部の環**(limbal ring)を赤黒く重ねた |
| シンプルな球体はつまらない、血管を造形して | 血管の濃さを高さとして扱い、**画面微分から法線を曲げる**(接線不要のバンプ)。隆起は太い索だけ(毛細血管まで盛ると小さい画面で砂粒になる)。さらに頂点側で強膜だけを低周波でうねらせ、完全な球をやめた(振幅 0.65%) |
| メタルチックだけど有機的に | 形は枝分かれのまま、**隆起した稜線だけ**粗さを 0.52 → 0.20 に落として鋭い光沢を返させ、その光沢に鋼と血の中間の色を与えた。地(粘膜)は鈍いまま |
| 黒い瞼に作って | 瞼の材質を黒へ(`0x08090b` → `0x040405`、環境の映り込み 0.55 → 0.16、艶 0.25 → 0.06)。色を黒くするだけでは金属反射でドームが灰色に見えるので、**映り込みと艶を落とす**のが本体。縁だけ `0x212327` で線として残す |

| 瞼に有機的なパイプで装飾 → もっと太くて格好の付く形 → 「時間をかけて格好いい配管を」 | 3 段階で作り直した。(1) 蛇行する細管 3 本 = 黒い瞼に沈んで読めない。(2) 等間隔の六角リブ = 目盛のようで面白みが無い。(3) **配管の条件を先に決めて設計**: 階層(太い幹 1 本 + 支線 1 本)/ 目的地(縁に沿って走り、**肘で折れて極へ上がり、ポートに刺さる**)/ 継手(肘にフランジ付きカラー、末端に六角のボス + ボルト)/ 素材差(管は磨いた黒鋼・継手は一段明るい削り出し・朱の帯は主ポートに 1 本だけ)。上下の瞼で流れの向きを変え、鏡写しにしない。瞼と同じ clipping plane で切るので、まばたきで一緒に消える |
| 黒目がパイプの上に浮いているバグ | 原因は**瞼の縁(clip plane)を跨いだ管**。片面ジオメトリの筒を平面で輪切りにすると向こう側が抜け、筒の中から眼球が見えていた(下瞼の幹が縁の緯度 1.08rad を 1.00〜1.12 で跨いでいた)。対策 2 本: (1) 管を縁から離す —— 瞼が最も開いたときの縁(上 0.94rad / 下 0.98rad)から管の半径 0.07 を引いた0.90rad 以内に幹の最も縁寄りの点を収める、(2) 管と継手を `DoubleSide` にして、まばたきで切られても筒の内壁が見えるだけにする |
| パイプのデザインをよりかっこよく | 構造(幹・肘・ポート)はそのまま、**密度**を足した: 幹の中央区間に蛇腹の環(可撓管の記号、InstancedMesh 1 本)、幹に沿って面の上を横へずらした細い並走ケーブル、支線の出口は環ではなく角張ったジャンクションブロック + 上面のボルト 2 本、ポートのボスにフランジ止めの小ボルト 3 本(120° 刻み)。継手と留め具が「本物」を作る —— 管そのものを増やしてはいない |
| パイプの赤い部分の状況別の発光 | `MODES` の各場面に `accent = { base, amp, hz, flicker }` を持たせ、`accentIntensity(mode, t)`(純関数)が朱の帯の `emissiveIntensity` を毎フレーム決める。中立 = 弱い残り火がゆっくり息をする / 建玉 = 脈が乗る / 武装 = 速い鼓動(1.7Hz) / 勝ち = 最も明るく速い(2.6Hz) / 負け = 消えかけの不規則な揺らぎ。bloom が乗るので明るいほど滲む。実測(赤の強い画素の総和): 中立・負け 465、武装 74k〜91k(脈)、勝ち 95k〜110k |
| ※ 遅延チャンクの予算超過 | 配管で eye3d の閉包が 666,937 B(上限 665,600)。上限は緩めず、vite の transform で **GLSL 文字列の中の行コメント**(minify に削られない・日本語は 3 B/字、eye3d だけで 5.9 kB)をビルド時に落とす `stripGlslComments` を入れた。結果 661,110 B(余裕 4.5 kB)。three-renderer が 621 → 635 kB に増えたのは配管で初めて使ったクラス(TubeGeometry / CatmullRomCurve3 / InstancedMesh)が tree-shaking で入った分で、変換の影響は −229 B |
| ※ 黒い瞼が効いていなかった | `buildLid` の `finish` が艶と映り込みを上書きしていた(色だけ黒で反射は旧値)。finish 側も 0.16 / 0.05 へ |

実測(描画結果のピクセル): 瞳の中 2 → 縁 6 → 虹彩 7〜15 → 輪部 15〜23 → 強膜 25〜51。
瞳の縁付近の赤み(R−G)は 1〜5 で強膜の 27 に対してほぼ中立 = 赤い輪は無い。輪部に白い突起は無い。

### 6. 角ばった吹き出しと張り詰めた書体(2026-09-07 追補)

- 丸みをやめ、**切り欠きのある多角形**(左上と右下を落とし、下辺から目へ鋭い舌)。角丸と
  `clip-path` は共存できないので輪郭は 1 枚の polygon。枠線は `clip-path` に切られるため、
  外側の面を縁の色・内側の疑似要素を 1px 内へ落として板の色にする **2 枚重ね**で 1px の縁を作る。
  影は `box-shadow` ではなく `filter: drop-shadow`(切り抜いた輪郭に沿う)。
- tone の色は縁(外側の面)の色で出す —— `box-shadow` の輪は `clip-path` では描けない。
- 書体は **Chakra Petch**(角を落とした技術系サンセリフ)500、16px。IBM Plex Mono より字面が
  締まり、短い一言が計器の警句に見える。読み込みは既存の Google Fonts の 1 リンクに相乗り。

## 規律

- `pet.js` は表示専用。view を読むだけで、判定・発注・保存・ネットワークに触れない(テストで禁止語)。
- 目の場面(neutral / long / short / 武装 / elated / dejected)は `renderPet()` が一手に決める。
  R60 まで `render()` の 3 箇所に散っていた `standbyEye.setMode()` は畳んだ。
- 駐在は広い画面だけ。電話(Telegram)の見え方は R60 のまま変えていない。
- 生 WAV(`tools/voice` の入力)は出荷しない。`public/voice` に置くのは加工済みだけ。
