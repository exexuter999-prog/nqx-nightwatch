## 1. 目標ラダー

`model_targets()` は DOL を**無条件で先頭**に置いていた。実測で DOL は
**64% の確率で最も遠い**目標なので、TP1 が runner より遠くなる。
発注契約は `splitPlan.targetCount = 2` を 3 箇所で独立に強制しており
(`nqx_state.py:375` / `state_machine.js:250` / `execution_intent.py:100`)、
`model_targets` は最大 3 本、`candidate_vp80` が `VA_TARGET` を足して最大 4 本
返していた。結果 **246 中 212 (86%) がブローカー到達前に拒絶**されていた。

候補の**列挙**と**順位付け**を分離した:

- `target_pool()` — 方向・最小 R・重複(`DEDUPE_PT` 2.0pt)を満たす候補を
  **距離順**で返す。DOL も VA_TARGET も同じ関門を通る
- `model_targets()` — TP1 = 最近接、runner = `PREFERRED_LABELS` か
  `tier <= RUNNER_TIER_MAX` を満たす最遠 rung。2 本か 0 本

`DEDUPE_PT` に `TICK` を使わないのは、0.25pt 差の 2 本が別 rung として
残ってしまうため。階層判定は R4 §3.1 の既存 `level_tier()` を再利用する
(最初 `level_tier` を重複定義してしまい、既存のテストが検出した)。

**ドキュメントからの意図的逸脱**: `operational-gates.md:656` の runner 引き戻し先
「tier ≤ 2」は月足/週足/前日のみで、実測では最遠 rung の 30/213 しか該当せず、
文字通り適用すると runner の約 86% が消える。**tier ≤3 + preferred** を採った。

### A+ ボーナスを runner へ移した

TP1 を最近接にすると `targetR[0]` の中央値が 2.42 → 1.96 に落ち、旧閾値
`MODEL_APLUS_R = 2.8` の発火率が 39% → 8% になって等級が一斉に下がる。
`MODEL_APLUS_RUNNER_R = 4.0` は新しい runner R の 61 パーセンタイル =
旧発火率 39% を再現する値。**リファクタを跨いで採点分布を一定に保つための
較正であって、存在しない実績への当てはめではない**（実トレード記録は 1 件）。

### 併せて直した契約違反

- `candidate_vp80` が `VA_TARGET` を `min_r` の**外側**で prepend していた。
  実データに `targetR[0] = 1.4` (< `MODEL_MIN_R`) が存在した。`target_pool` の
  `extra` 経由に変え、同じ関門を通す

## 2. 反転を先回りする指値

エンジンは `COMPLETE_STATES`(`RETEST_HELD` / `FLIP_HELD`)しか候補化して
いなかった。チェーンは `SWEEP_CANDIDATE → SWEEP_CONFIRMED → MSS_CONFIRMED
→ RETEST_HELD` と進む。**`MSS_CONFIRMED` の時点で**:

- 掃引は**既に起きている** → SL の根拠(掃引極値)が**実測で確定**している
- リテストは**まだ来ていない** → 建値が現値の先にある = **指値として置ける**

実測（372 サイクル）: `MSS_CONFIRMED` は **216 回**、`RETEST_HELD` は **70 回**。
待つことで機会の約 2/3 を捨てていた。`MSS_CONFIRMED` の **99% (213/216)** が
建値を現値の先に持ち、リスク中央値 27.5pt・**94% が 60pt 上限内**だった。

`order.py:784-792` は即約定する指値を拒否する（買いは建値 < 現値、売りは
建値 > 現値）。`_resting_limit_ok()` で同じ向きを要求する。`LIMIT` は既に
本番既定の注文種別で（`order.py:851`）、`ENTRY_RESTING` も
`ownership_binder` / `autotrade_engine` / 実行契約が既に扱う。

`LIMIT_MAX_GAP_R = 1.5` — 現値から建値までが 1.5 リスクを超える指値は
待ちが長すぎる。適用後 41 本、gapR 中央値 1.19、リスク中央値 22.5pt。

### 測定して棄却した案

**「未掃引の流動性プールに先回りして指値」**。掃引イベント 100 件を観測すると
**89% が 36 分以内に水準の内側へ戻る**（ICT の前提は強く成立）。しかし
行き過ぎ幅は中央値 21.5pt / p75 50.5pt / **p90 82pt**。プール直上の SL
(3×buffer = 25.7pt) が耐えるのは **58%** で、88% 耐えるには 68.5pt 必要 ——
**60pt の SL 上限を超える**。掃引の極値は起きるまで分からないので、
先回りするなら SL は推測になる。`MSS_CONFIRMED` を待てば実測になる。

**「初出の瞬間に出せば速い」**。初出(seq=0)でも reachR の 53% が 1R 超で、
速く動いても解決しない。建値を現値の**先**に置くことが必要だった。

**「FVG を建値にする」**。適格 FVG のある 89 候補で FVG 端の建値は
`|現値−建値|/リスク` 中央値 **2.04R**、レベル建値の **1.43R** より**遠い**。
教科書的には正しく聞こえるがこのデータでは改悪。
