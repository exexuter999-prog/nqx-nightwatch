## 1. High RR トレードの機械的定義(この指示書のスコープ)

```
High RR トレード = 計画 RR ≥ 2.8R(ドクトリン TP2 水準)の区画を含む
                   「管理計画」がエントリー提示と同時に宣言されたトレード
```

型は2つ。どちらも**エントリー条件(msnr_gate / ボラ / CT_TREND / dayguard /
イベント封鎖)は従来と完全に同一**。変わるのは出口の設計だけ:

| 型 | 構成 | 適用条件 |
|---|---|---|
| **分割型** | 2枚。1枚目 TP1(1.8R 目安の構造)、2枚目ランナー(TP なし・SL 共有 → TP1 到達で建値移動 → トレール) | SL ≤ 26pt(2枚 × 26pt = $104 ≤ $105)に収まる構造のみ |
| **単枚ランナー型** | 1枚。TP なしで発注(order.py は TP 省略を受理する・実測済み)。TP1 相当価格の**通過**で建値移動 → トレール | SL 26〜52pt の構造。部分利確は物理的に不可能なので全量ランナー |

**管理計画の必須5項目**(1つでも欠けた提示は不合格 — §2 提示フォーマットと同格):

```
1. TP1 価格(分割型=1枚目の実 TP / 単枚型=建値移動のトリガー価格)
2. 建値移動の条件(「TP1 到達で」以外を使うなら理由)
3. トレール方式: NQX_DATA_CT_TRAIL 追従 or 「守りたい額」(TRADING_CONTEXT §6 原則1)
4. ランナー最終目標: HTF 構造(tier ≤2 レベル / CT レール)を価格で。「伸ばせるだけ」は不可
5. 時間切れ: セッション終了(JST 04:00)までに残っていれば成行手仕舞い
```

## 4. Phase C — RR 潜在値の観測(ADVISORY・武装可否に不影響)

msnr_gate に `rrPotential` を追加する。**promotion / allowed / grade には
一切影響しない**(R4 原則1: まず ADVISORY で 3営業セッション)。

### 4.1 機械的定義

各レベル L(non-dynamic)・各 side について:

```
sl_proxy = noiseFloor + touchTol          # SL 距離の下限代理(構造緩衝+空気)
利益方向 = BUY なら L より上、SELL なら L より下
rb1, rb2 = 利益方向にある non-dynamic レベルを近い順に2つ
           (|rb − L| ≥ 3 × touchTol を満たすものだけ数える)
rrPotential = {
  "rb1Pt": |rb1 − L|,  "rb1R": rb1Pt ÷ sl_proxy,     # TP1 の走路
  "rb2Pt": |rb2 − L|,  "rb2R": rb2Pt ÷ sl_proxy,     # ランナーの走路
}                                          # 該当レベルが無ければ null(走路は開放)
```

- 出力は promotion を持つレベルの `chains` と同階層に `rrPotential` を追加
- `--card` の advisory 行に最有望1件だけ載せる:
  `走路 rb2 4.1R(PDH まで 118pt)` の形式。4096 バイト縮小順は
  既存規則の advisory 内で最後尾(最初に削られる)
- `rb2R ≥ 2.8` のとき「高RR候補」の接頭辞を付ける(表示のみ)

### 4.2 テスト(合成3本+回帰1本)

- `test_rr_potential_two_roadblocks`: 上に2レベル → rb1/rb2 とも数値
- `test_rr_potential_open_runway`: 利益方向にレベルなし → null
- `test_rr_potential_ignores_dynamic_and_near`: VWAP 系と 3×tol 未満は飛ばす
- `test_rr_potential_does_not_change_promotion`: 165 実データで
  allowed の集合が R7 時点と**完全一致**(これが最重要の回帰)
