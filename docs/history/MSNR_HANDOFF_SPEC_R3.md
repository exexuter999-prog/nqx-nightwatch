## 0. 裁定と承認事項

- **①を採用する**(revisit/保持の判定足はレベル価格そのものに到達していること)。
  ②(ゾーンへ1tick侵入)は却下 — tol が広い晩は依然「レベルの 1.75pt 手前」が
  保持として通り、同じ穴が残る。③(tol 上限)は不要 — 本修正で到達判定が
  tol に依存しなくなり、tol の他の用途(破壊・受容・タッチ計数)はノイズに
  スケールするのが正しい挙動のため。**③は適用しない**
- R2 §1.4 の前提(「保持クローズが出る前に武装した」)は Trade 2 について
  **事実誤認だった**。Opus 5 の実測診断(保持は武装の10分前に確定・
  revisit は 0.05pt 成立)を全面的に採用する
- 21時台10件の再判定報告も受理。R2 §0 の「CONSUMED 較正誤りが allowed
  ゼロの主因」はこの10件には当たっていなかった(エピソード数は真に3)。
  エピソード計数への修正自体は正しいので**維持**
- 採用理由(§9 に1段落で転記すること): ユーザー自身の 8/17 敗因分析は
  「**適切な戻りまで待機できていなかった**」。①はこれをそのまま数値化した
  ものである — 戻りがレベルに到達していないなら、論拠はまだ試されていない。
  0028/0031 の「保持」はレベル 30,253 の 2pt 手前で止まった戻りであり、
  実際にレベルが試された 00:42 に構造は死んだ

## 1. 定義変更(1箇所・両連鎖に適用)

**到達条件を新設する。** リテスト/保持の判定足は、その極値が
**レベル価格そのものに到達**していること:

```
BUY 側:  l ≤ P
SELL 側: h ≥ P
```

- **SWEEP 連鎖の RETEST_HELD** と **FLIP 連鎖の FLIP_HELD** の両方の
  revisit 判定に適用する(片方だけ直すと同じ穴が残る)
- クローズ条件(BUY: `c > P` / SELL: `c < P`)は従来どおり
- **原則**: 「ゾーン(P±tol)はタッチ計数・破壊・受容の分類にのみ使う。
  **到達の判定には使わない**」— この一文を operational-gates.md §9 に明記
- 連鎖リセット条件(`c` が P∓tol を超える)は変更しない
