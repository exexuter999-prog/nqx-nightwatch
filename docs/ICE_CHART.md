# 氷チャート — 価格予測の立体投影

2026-08-24。ミニアプリのチャートに、計画を透明な立体の氷ローソクで
未来ゾーンへ投影する機能を入れた。併せて、描画されていなかったゾーンを
描けるようにした。

## 0. 3D への作り直し（2026-08-24 追記）

初版は SVG の擬似アイソメ（面を 3 枚重ねただけ）で、厚みも映り込みも無く
「透明な立体の氷」になっていなかった。**three.js の実メッシュ**に作り直した
（`telegram_mini_app/icescene.js`）。

**屈折(`transmission`)は使えない。** 最初 `MeshPhysicalMaterial` に
`transmission: 1, ior: 1.31`（氷の屈折率）で組んだが、**不透明な色板**に
なった。WebGL の透過はシーン内の背後しか屈折させられず、キャンバスの
**下にある DOM のチャートは屈折対象にならない**。氷らしさは
環境マップの映り込み + `clearcoat` + `flatShading` の稜線で出し、
下のチャートは素直にアルファ合成で透かしている。

その他の設計判断:

- **カメラはピクセル空間の正射影。** `chart.js` が price→px を済ませた矩形を
  渡すので、3D 側は価格を一切知らず、SVG のグリッドと 1px もずれない
- **ジオメトリは 1 個だけ作って共有**し、ブロックごとに非一様スケールする。
  `ExtrudeGeometry` + `Shape` は三角形分割器まで抱き込んで遅延チャンクを
  **29KB** 増やし予算(665,600B)を超えた。八角柱(`CylinderGeometry` の
  `radialSegments=8`)をスケールすれば同じ断面が得られ、描画ごとの
  ジオメトリ確保もゼロになる
- **各ブロックを X に -0.26 rad 傾ける。** 正射影 + Y 回転だけでは上面が
  一度も見えず、平たい板が明滅しているようにしか読めない
- 環境マップは手続き生成（128×256 の canvas）。裏を向いた面が真っ黒に
  落ちないよう、反対側にも弱い光を置いてある
- WebGL が無い環境では SVG の氷へ落ちる。three.js は遅延読み込みで、
  3D 依存が発注ゲートを遅らせない（`app.js:56-66` と同じ規律）

### 読ませるための 3 つ

氷塊だけを並べると「散らばった板」にしか見えず、計画がひと続きの筋である
ことが読めなかった。デザインとして次の 3 つを足した。**どれも見た目のために
情報を足しておらず、既にある値の見せ方を変えただけ**。

1. **軌道**（`renderProjectionPath`）— 現値と各足の終値を結ぶ 1 本の線。
   氷の**下**に敷く（氷が主役）。先へ行くほど薄くなるグラデーション
2. **確度の減衰** — 先の足ほど薄い氷にする。遠い足ほど当然あやふやなので、
   透明度に素直に出す。マテリアルを足ごとに作るとシェーダが増えるので、
   4 段に切って使い回す（`CONFIDENCE_TIERS`）
3. **pivot の強調** — 建値の足だけ厚く・明るく・粗さを落とす。SL まで伸びる
   ヒゲを持つのもこの 1 本だけなので、「どこで何を賭けているか」が一目で分かる

## 1. 氷のろうそく足(`telegram_mini_app/icecandles.js`)

**これは相場の予測ではなく、計画そのものの投影**。描く価格はすべて
シナリオが既に持つ 4 つのアンカー(現値 / 建値 / SL / 目標)の凸包の内側にあり、
そこから外れる値を発明しない(`pathcandles.js` と同じ規律。テストで固定)。

形:

| 相 | 内容 |
|---|---|
| `approach` | 現値 → 建値。指値が約定を待つ区間 |
| `pivot` | 建値の足。**この足だけ**ヒゲが SL まで伸び、許容する逆行の深さを見せる |
| `run` | 建値 → 目標 |

方向は **幾何から導く**(`stop < entry` なら買い)。`side` のラベルは
`SHORT` / `SELL` / `short` と揺れるため判定に使わない。実際、最初の実装で
ラベル依存にしたところデモの `SELL` で一本も描かれなかった。

立体は等角の三面体(前面 + 上面 + 側面)を 1 つの `<g class="ice-solid">` に
まとめ、面取りした 8 頂点のポリゴンで角を作る。矩形は使わない。
塗りは `linearGradient` の半透明で、稜線だけ細く光らせる。

**回転**: 1 秒に一回転(`ice-spin`)。`perspective: 420px` を掛けているのは、
透視投影が無いと `rotateY` が 90 度で幅 0 に潰れて氷が消えるため。
各足は `--ice-i` で位相を 0.06 秒ずつずらし、一列が同時に薄くならないようにする
(周期は 1 秒のまま)。`prefers-reduced-motion` で停止する。

未来ゾーンの足幅は 3 分足とは独立に決める(`pitch * 0.78`)。同じ細さだと
氷の厚みが 1px 未満になり立体が消えるため。武装時の `futureSlots` を
`max(12, count * 0.3)` へ広げて場所を作った。

## 2. 死んでいたゾーン描画を生き返らせた

`chart.js:520-527` は `strategyOverlays.crt` と `.liquidity` を読んでいたが、
クライアント側の facade がそのキーを作っていなかった。**R14 経路では
CRT レンジと BSL/SSL 流動性プールが一度も描かれていなかった**。
データは `matrix.models.crt` / `matrix.models.liquidity.pools[]` に来ている。
facade に 2 行足しただけで描画される。

## 3. ゾーン名の描画

`name` / `nameColor` を設定しているのに描画されず、`fitText` / `shortName` /
`nameLane` が丸ごと死にコードだった。左端の細いレーンに等幅で出す
(価格軸は汚さない)。既存の `spreadLabels` の衝突回避と優先度間引きに乗せる。
実測で画面内のレベルは中央値 16 本・最大 26 本あるため、間引きは必須。

## 検証

`npm test` **85 件**通過(うち `test/icecandles.test.mjs` 9 件が新規)。
`npm run build` → `npm run verify:build` の予算内
(entry 164KB / 512KB、遅延チャンク 623KB / 665KB)。
`https://50d1a0f6.nqx-nightwatch.pages.dev` へデプロイ済み。

テストが実データの不整合を 1 件捕まえた: 実体には見えるようにする 3px の
下限があるのにヒゲには無く、**実体より短いヒゲ**ができ得た。ヒゲは定義上
つねに実体を含むので、同じ下限を掛けるように直した。

## やっていないこと

エンジン側は一切触っていない。別途、実測に基づく以下が控えている:

- 目標ラダーの修正。246 シナリオ中 **212 (86%)** が目標の本数・順序の不整合で
  ブローカー到達前に拒絶されている(発注契約は「ちょうど 2 本」を 3 箇所で強制、
  一方 `model_targets` は最大 4 本返す。DOL は 64% の確率で最も遠い)
- `MSS_CONFIRMED` の指値モデル。掃引済み(SL の根拠が確定)かつリテスト未到達
  (指値が置ける)状態が 372 サイクル中 216 本あり、**99% が建値を現値の先に持つ**
  = `order.py:784-792` がサンクションする向きと一致。現在エンジンは
  `RETEST_HELD`(70 本)しか候補化しておらず、機会の約 2/3 を捨てている
- ICT データ取得手順の明文化。`rangeAnchor` は 403/403 で `RANGE_ANCHOR_REQUIRED`
