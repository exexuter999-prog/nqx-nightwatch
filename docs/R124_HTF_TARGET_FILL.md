# R124: 上位足の水準で利確目標の不足だけを埋める(2026-09-21)

## 1. 何が起きていたか

2026-09-21 16:28 / 16:31 JST、`BREAKER_CONTINUATION BUY`(A → A+)が `TARGET_HEADROOM_INSUFFICIENT`
で WATCH のまま primary なしになった。建値 30,128.75 / SL 30,085.75(43pt)に対し、上の水準は
London High 30,162.75(+0.8R)だけ。`model_targets` は 1.5R 以上の目標を 2 本要求するので 0 本になる。

水準マップはセッション系 9 本(POC/VAH/VAL・6pm open・Weekly open・Asia/London 高安)だけで、
前日高安や上位足のスイングは目標候補に無かった。高値更新の局面ではどの BUY も目標不足で落ちる。
機械的な不具合ではなく、戦略の設計の穴。

## 2. 変更

- `htf_targets.py`: 確定した上位足だけから水準を作る(前日高安 / 前週高安 / 未回収の日足スイング /
  1h・4h の 20 本レンジ高安)。ラベルは `HTF ` 接頭辞(階層 `level_tier` は変わらない)。
- `msnr_gate.model_targets`: 目標が 2 本揃わないときだけ、上の水準を足して引き直す。揃っている
  候補には触れない。水準は `evaluate()` が入口で `contextvars` に積み、出口で必ず戻す
  (evaluate の外では R124 以前と同じ)。
- 契約 `htfTargets`: `mode` = OFF / LIVE、`sources` = 使う水準。**2026-09-21 ユーザー決定で LIVE
  (SHADOW は省略)**。戻しは `mode` を `OFF` にする 1 語。
- 水準マップ(セットアップ検出・SL の流動性逃がし)には入れない。Entry / SL / 枚数 / decisionId は
  変わらない(decisionId は目標を含まない)。契約の `version` も変えないので Worker は無関係。
