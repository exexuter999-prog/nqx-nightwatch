# R25 ストラテジーエンジンのオーバーホール

2026-08-24。実サイクル 403 本(`.secrets/monitor_cycle_*.json`、約 20 時間分)を
現エンジンで再生し、見つかった構造欠陥を直した。

## 何が起きていたか

| 指標 | 修正前 | 修正後 |
|---|---|---|
| 403 本中の武装(A/A+ ARMED) | **199**(49%) | **0** |
| 武装のうち SL > 60pt または R < 1.5 | 約 57(A+ の SL が 78〜116pt) | 0 |
| 武装のうち独立確認ゼロ | 199(全部) | 0 |
| 同一セットアップの最長連続武装 | 14 サイクル | — |
| 実トレード記録 | 1 件 | 1 件 |

3分足の監視で 2 回に 1 回「発注可」を出し、その全てが独立確認ゼロだった。

## 直した欠陥

### 1. VP80 が別のトレードの幾何で採点されていた

`candidate_vp80()` は「VA edge の価格」で `_candidate_for_chain()` を呼んで
採点し、**その後で** `entry` / `stop` を上書きしていた。SL 上限(60pt)も
R 判定も上書き前の値で通過するので、実際に出す注文とは無関係に A+ になる。
さらに SL を窓内 60 本の最高値から取るため、100pt 超になっていた。

OTE で前日直した欠陥と同じ構造。最終幾何をそのまま採点に渡す経路へ統一した。

### 2. 幾何の不変条件が「採点時」にしか無かった

採点後に `entry` / `stop` / `targets` を差し替える経路が複数ある以上、採点時の
判定だけでは最終値を保証できない。`_finalize_candidate()` に
`_geometry_blockers()` を入れ、**どの経路でも**最終値に対して

- SL 距離 ≤ `sl_cap_pt()`
- 先頭目標の R ≥ `MODEL_MIN_R`
- 方向と価格の並びの整合

を検証する。これで今後同種の欠陥が入っても武装には至らない。

### 3. VP80 が復帰済みの目標を追いかけていた

VA 復帰は「エッジから反対側のエッジへ」の型。建値が既に目標側へ抜けている
状態でも候補化し、目標が建値の反対側に出ていた(53 件)。復帰済みなら候補に
しない。

### 4. 「位置が逆」の虚偽ラベル

`PREMIUM_DISCOUNT_WRONG_SIDE` が、レンジ(rangeAnchor)を取得していない
ときにも付いていた。403 本中 rangeAnchor は **0 本**。つまり「逆側にいた」
のではなく「一度も見ていなかった」。`RANGE_ANCHOR_MISSING` に分離し、
本当に逆側のときだけ減点(−2、SMT 逆行と同じ重さ)する。

### 5. decisionId に時刻が混ざっていた

同じセットアップが 3 分ごとに別 ID になり、下流の重複防止が効かない。
構造キー `setupId`(モデル・方向・レベル・起点の足・SL)を導入し、
decisionId はそこから導出する。建値は現在値に追従して動くので含めない。

### 6. 構造だけで A に届いていた

チェーン完成 3 + レジーム適合 2 + R ≥ 2.8 で 2 = 7 点 = A。確認要素が
一つも無くても武装する設計だった。**A/A+ には構造と独立したデータ源の
確認が最低 1 つ要る**(`NO_CONFIRMATION` ハードブロッカー):

`ICT_LOCATION`(HTF アンカー)/ `SMT_ALIGNED`(相関銘柄)/ `CVD_ALIGNED`・
`CBC_ALIGNED`(注文フロー)/ `PO3_ALIGNED`(セッション構造)/
`IMAGE_MODEL_ALIGNMENT`(カタログ合議)/ `OTE_FVG_CONFLUENCE`

displacement と VP 受容は価格構造そのものなので**含めない**。最初含めたら
39 本が displacement だけで武装したので外した。

## 「武装 0」の意味

修正後の 403 本で武装が 0 なのは退行ではない。この 403 本には独立確認の
入力(rangeAnchor / peers / CVD bias / CBC / po3)が**一つも取得されていない**。
エンジンは「確認が無いなら出さない」を正しく実行している。

これまでの 199 武装は、確認ゼロのまま出ていた。

## 次に必要なこと(エンジン外)

独立確認の入力を取らない限り、このエンジンは正しく何も出さない。
CLAUDE.md §6.2a の R13 取得手順を監視サイクルに組み込むこと:

- `rangeAnchor`(15M 以上の HTF レンジ)
- `peers`(ES / YM の同時刻足)→ SMT
- CVD の bias と鮮度
- `po3`

`decision.ictCoverage` が何が欠けているかを毎サイクル記録する。

## 触っていないもの

- 4 モデルの構造検出(スイープ→MSS→リテスト、ブレイク→受容)
- 採点の配点。変えたのは「確認ゼロでも A」を塞いだことと、位置逆行の減点
- 実行契約・ULTRA・発注経路
