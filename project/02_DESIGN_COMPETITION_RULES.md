# Design Competition Rules

## 1. 三案は構造的に異なること

| Direction | Required character | Must differ in |
|---|---|---|
| Institutional Clarity | 静か、精密、常時監視向け | ペイン構成、色数、情報密度 |
| Precision Glass | Glassを操作・ナビ層へ限定 | 浮遊コントロール、状態反応、背景分離 |
| Radical Data-First | 情報順序をゼロから再構成 | IA、Chart/Level/Scenarioの関係、モバイル |

色、角丸、背景だけを変えた案は失格。

## 2. 各案の必須成果

- 一文コンセプト
- 1440pxテキストワイヤーフレーム
- 390pxテキストワイヤーフレーム
- 常時表示情報
- 隠す／折りたたむ情報
- Glassを使う場所／使わない場所
- 現行から削除する上位10要素
- 最大の利点3つ
- 最大のリスク3つ
- 実装コスト S / M / L
- Scorecard

## 3. 採用規則

- 85点以上
- 全評価項目7/10以上
- 同点時は Data Legibility、Level/Price Hierarchy、Mobileの順で決定
- 合格案がなければ最上位案を1回だけ改善し再採点
- 採用後は他案を混ぜない。勝者の論理を維持する

## 4. Creativity Boundary

自由に変更可能:

- レイアウト
- 表示順
- CSSと視覚言語
- 装飾の削除
- ペインの統合
- モバイル導線
- 詳細の段階的開示

保護対象:

- NQX/1データ契約
- パーサーとバリデータ
- リスク監査の意味
- FAST / DEEPの意味
- 安全な拒否動作
- 市場データと推定の区別

## 5. Quality Gate

次の質問へ即答できなければ採用不可。

1. 今の価格はどこか
2. 一番近い上のレベルは何か
3. 一番近い下のレベルは何か
4. 今はWAITかEXECUTEか
5. 選択シナリオの状態は何か
6. Entry、Invalidation、Hard SL、TP1はどこか
7. なぜ今エントリーしないのか
8. データはLIVE、SNAPSHOT、STALE、NO OHLCのどれか
9. 競合シナリオは何で無効になるか
10. 次の30分で何を見るか
